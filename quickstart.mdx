This guide walks through every step required to add a GeckoLib-animated entity to your mod. By the end you will have a working entity with an idle loop animation, a `GeoModel` that resolves your JSON assets, and a renderer wired up to the vanilla entity renderer registry.

The examples below use a `CoolEntity` as the subject throughout all five steps.

<Steps>
  <Step title="Create a Blockbench model and export your assets">
    Open [Blockbench](https://www.blockbench.net/) and create a new **GeckoLib Entity** project. Model your entity using the bone/group structure you want, then animate it on the timeline.

    When you are ready, export two files into your mod's `resources/` directory:

    - **Geometry** (`File → Export → Export GeckoLib Entity`) → save to  
      `src/main/resources/assets/<modid>/geo/entity/cool_entity.geo.json`
    - **Animations** (`Animate` tab → `File → Export Animations`) → save to  
      `src/main/resources/assets/<modid>/animations/entity/cool_entity.animation.json`

    Place your texture file at:
    `src/main/resources/assets/<modid>/textures/entity/cool_entity.png`

    <Note>
      The path layout above matches the convention used by `DefaultedEntityGeoModel`. If you place your files somewhere else, you will need to return custom `Identifier` values from `getModelResource`, `getTextureResource`, and `getAnimationResource` in your `GeoModel` class.
    </Note>
  </Step>

  <Step title="Create your GeoModel class">
    `GeoModel` is the bridge between GeckoLib and your JSON assets. It tells the renderer where to find the geometry, texture, and animation files for a given render pass.

    `DefaultedEntityGeoModel` handles the path resolution for you, automatically prepending the `entity/` subdirectory and appending the correct file extensions based on your entity type's registered name.

    <Tip>
      Use `DefaultedEntityGeoModel(EntityType)` whenever your asset filenames match your entity's registered registry name. Pass the entity type to the constructor and GeckoLib derives all three resource paths automatically — no need to override any methods.
    </Tip>

    ```java CoolEntityModel.java
    import com.geckolib.model.DefaultedEntityGeoModel;
    import net.minecraft.world.entity.EntityType;

    public class CoolEntityModel extends DefaultedEntityGeoModel<CoolEntity> {

        public CoolEntityModel(EntityType<CoolEntity> entityType) {
            // Resolves paths like:
            //   geo/entity/cool_entity.geo.json
            //   animations/entity/cool_entity.animation.json
            //   textures/entity/cool_entity.png
            super(entityType);
        }
    }
    ```

    If you need full control over asset paths — for example, when multiple entity types share a model — extend `GeoModel` directly and override all three methods:

    ```java CoolEntityModel.java (manual paths)
    import com.geckolib.model.GeoModel;
    import com.geckolib.renderer.base.GeoRenderState;
    import net.minecraft.resources.Identifier;

    public class CoolEntityModel extends GeoModel<CoolEntity> {

        private static final Identifier MODEL      = Identifier.fromNamespaceAndPath("mymod", "geo/entity/cool_entity.geo.json");
        private static final Identifier TEXTURE    = Identifier.fromNamespaceAndPath("mymod", "textures/entity/cool_entity.png");
        private static final Identifier ANIMATIONS = Identifier.fromNamespaceAndPath("mymod", "animations/entity/cool_entity.animation.json");

        @Override
        public Identifier getModelResource(GeoRenderState renderState) {
            return MODEL;
        }

        @Override
        public Identifier getTextureResource(GeoRenderState renderState) {
            return TEXTURE;
        }

        @Override
        public Identifier getAnimationResource(CoolEntity animatable) {
            return ANIMATIONS;
        }
    }
    ```
  </Step>

  <Step title="Implement GeoEntity on your entity class">
    `GeoEntity` extends `GeoAnimatable` with entity-specific helpers such as `triggerAnim()` and `stopTriggeredAnim()` for server-side animation triggering.

    You must implement two methods:

    - **`registerControllers`** — Create your `AnimationController` instances here and register them. Each controller is responsible for one animation track.
    - **`getAnimatableInstanceCache`** — Return the per-instance cache that holds animation state. Create it once in the constructor using `GeckoLibUtil.createInstanceCache(this)` and store it as a field.

    `RawAnimation` is a builder that defines which animations play in what order. Cache instances statically — they are immutable and constructing them on every frame wastes allocations.

    ```java CoolEntity.java
    import com.geckolib.animatable.GeoEntity;
    import com.geckolib.animatable.instance.AnimatableInstanceCache;
    import com.geckolib.animatable.manager.AnimatableManager;
    import com.geckolib.animation.AnimationController;
    import com.geckolib.animation.RawAnimation;
    import com.geckolib.util.GeckoLibUtil;
    import net.minecraft.world.entity.EntityType;
    import net.minecraft.world.entity.PathfinderMob;
    import net.minecraft.world.level.Level;

    public class CoolEntity extends PathfinderMob implements GeoEntity {

        // Cache RawAnimation instances statically — they are immutable
        private static final RawAnimation IDLE = RawAnimation.begin().thenLoop("animation.cool_entity.idle");
        private static final RawAnimation WALK = RawAnimation.begin().thenLoop("animation.cool_entity.walk");

        // One cache per entity instance — created once, returned every call
        private final AnimatableInstanceCache animCache = GeckoLibUtil.createInstanceCache(this);

        public CoolEntity(EntityType<? extends CoolEntity> type, Level level) {
            super(type, level);
        }

        @Override
        public void registerControllers(AnimatableManager.ControllerRegistrar controllers) {
            // A single controller drives the idle/walk blend
            // The integer 5 is the transition tick count between animation switches
            controllers.add(new AnimationController<>(this, "movement", 5, state -> {
                if (state.isMoving()) {
                    return state.setAndContinue(WALK);
                }
                return state.setAndContinue(IDLE);
            }));
        }

        @Override
        public AnimatableInstanceCache getAnimatableInstanceCache() {
            return this.animCache;
        }
    }
    ```

    The integer `5` passed to `AnimationController` is the transition tick count — the number of ticks GeckoLib uses to interpolate when switching animations. Adjust it to taste.
  </Step>

  <Step title="Create your GeoEntityRenderer and register it">
    `GeoEntityRenderer` extends the vanilla `EntityRenderer` and implements `GeoRenderer`. Pass your `GeoModel` instance to its constructor.

    ```java CoolEntityRenderer.java
    import com.geckolib.renderer.GeoEntityRenderer;
    import net.minecraft.client.renderer.entity.EntityRendererProvider;

    public class CoolEntityRenderer extends GeoEntityRenderer<CoolEntity> {

        public CoolEntityRenderer(EntityRendererProvider.Context context) {
            super(context, new CoolEntityModel(MyMod.COOL_ENTITY_TYPE.get()));
        }
    }
    ```

    Register the renderer during the client-side entity renderer registration event. The registration API differs between loaders:

    <Tabs>
      <Tab title="Forge">
        ```java ClientSetup.java
        import net.minecraftforge.api.distmarker.Dist;
        import net.minecraftforge.client.event.EntityRenderersEvent;
        import net.minecraftforge.eventbus.api.SubscribeEvent;
        import net.minecraftforge.fml.common.Mod;

        @Mod.EventBusSubscriber(modid = "mymod", bus = Mod.EventBusSubscriber.Bus.MOD, value = Dist.CLIENT)
        public class ClientSetup {

            @SubscribeEvent
            public static void onRegisterEntityRenderers(EntityRenderersEvent.RegisterRenderers event) {
                event.registerEntityRenderer(MyMod.COOL_ENTITY_TYPE.get(), CoolEntityRenderer::new);
            }
        }
        ```
      </Tab>
      <Tab title="Fabric">
        ```java MyModClient.java
        import net.fabricmc.api.ClientModInitializer;
        import net.fabricmc.fabric.api.client.rendering.v1.EntityRendererRegistry;

        public class MyModClient implements ClientModInitializer {

            @Override
            public void onInitializeClient() {
                EntityRendererRegistry.register(MyMod.COOL_ENTITY_TYPE, CoolEntityRenderer::new);
            }
        }
        ```
      </Tab>
      <Tab title="NeoForge">
        ```java ClientSetup.java
        import net.neoforged.api.distmarker.Dist;
        import net.neoforged.bus.api.SubscribeEvent;
        import net.neoforged.fml.common.EventBusSubscriber;
        import net.neoforged.neoforge.client.event.EntityRenderersEvent;

        @EventBusSubscriber(modid = "mymod", bus = EventBusSubscriber.Bus.MOD, value = Dist.CLIENT)
        public class ClientSetup {

            @SubscribeEvent
            public static void onRegisterEntityRenderers(EntityRenderersEvent.RegisterRenderers event) {
                event.registerEntityRenderer(MyMod.COOL_ENTITY_TYPE.get(), CoolEntityRenderer::new);
            }
        }
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Test in-game">
    Build your mod and load it in a test world. Spawn your entity with `/summon mymod:cool_entity`. You should see the idle loop animation playing immediately, with the walk animation blending in when the entity moves.

    If the entity appears with no model or a missing texture, check that:

    - Your `.geo.json`, `.animation.json`, and `.png` files are in the correct `resources/` paths.
    - The animation names in `RawAnimation` exactly match the names in your `.animation.json` file (they are case-sensitive).
    - `GeckoLibConstants.init()` is called during mod startup (see [Installation](/installation)).

    <Note>
      GeckoLib logs warnings to the console when an `AnimationController` references an animation name that does not exist in the loaded JSON file. Check your logs if an animation is not playing.
    </Note>
  </Step>
</Steps>
